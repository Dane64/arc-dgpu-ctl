# Releasing

`VERSION` is the **only** place the version is written. Everything else is
derived from it at build time:

| Derived | How |
|---|---|
| `arc-dgpu-ctl version` | `make build` / `install.sh` substitute `@VERSION@`; a source checkout reads `VERSION` at runtime |
| `debian/changelog` | generated by `make debian/changelog` (not in git); `-rc1` becomes `~rc1` |
| tarball / `.deb` names | from `VERSION` |
| GitHub release | tag must equal `v` + `VERSION` - the workflow checks it |

## Steps

1. `main` is green; notes are under `## [Unreleased]` in `CHANGELOG.md`.
2. Set the version and rename the changelog heading:
   ```sh
   echo 3.6.0 > VERSION
   sed -i 's/^## \[Unreleased\]/## [Unreleased]\n\n## [3.6.0]/' CHANGELOG.md
   make check
   ```
3. Commit, tag, push:
   ```sh
   git commit -am "Release v3.6.0"
   git tag -a v3.6.0 -m v3.6.0
   git push --follow-tags
   ```
4. `release.yml` re-runs CI, checks tag == `VERSION`, builds
   `arc-dgpu-ctl_3.6.0_all.deb` (Debian testing) and the source tarball, writes
   `SHA256SUMS`, and publishes the release. Notes come from the `## [3.6.0]`
   section, or GitHub's generated notes if that section is missing.
5. Close milestone `v3.6.0`; bump the submodule in parent projects.

Pre-release: `echo 3.6.0-rc1 > VERSION`, tag `v3.6.0-rc1` → marked as
pre-release, Debian version `3.6.0~rc1`.

**major** = CLI contract change, **minor** = new commands / hardware,
**patch** = fixes. Never reuse a published version: delete a broken release
and ship the next patch.

## Local build

```sh
sudo apt install build-essential debhelper lintian
make deb && lintian dist/*.deb
```
